## 1. Architectural Baseline & Principles

Exvorta's digital presence serves institutional global trade partners, requiring a strict WCAG 2.1 AA accessibility bar with zero compromises on design fidelity. The architecture enforces four non-negotiable principles:

1. **Semantic Landmarks & Skip Navigation:** Assistive technologies must have direct access to primary navigation landmarks, with a persistent skip navigation mechanism on every public route.
2. **Standardized Focus Indication:** Keyboard focus indicators must never be suppressed. High-contrast `:focus-visible` rings adhere strictly to design tokens across light and dark theme sections.
3. **Explicit Labeling & Robust Form Controls:** Every interactive control and input field must have explicit programmatic label associations, clear required indicators, and assertive live region error announcements.
4. **WCAG-AA Color Contrast Compliance:** Text, active controls, and icons adhere to contrast ratios of at least 4.5:1 for standard text and 3:1 for large display typography and graphical interface elements.

## 2. Landmark Architecture & Skip-to-Content

### Primary Page Landmark
All route views must render through `components/layout/PageWrapper.tsx` (or an equivalent layout wrapper) providing exactly one semantic `<main id="main-content">` landmark. Redundant nested `<main>` tags inside page components are strictly prohibited:
```tsx
// components/layout/PageWrapper.tsx
<main id="main-content" className="relative z-10 flex w-full flex-1 flex-col">
  {children}
</main>
```

### Skip Navigation Link
The global skip link is anchored in `app/(frontend)/layout.tsx` via `components/legal/SkipToContent.tsx`. It remains visually hidden until focused via the `Tab` key:
```tsx
// components/legal/SkipToContent.tsx
<a
  href="#main-content"
  className="sr-only focus:not-sr-only focus:absolute focus:top-4 focus:left-4 focus:z-50 focus:p-4 focus:bg-surface focus:text-accent focus:font-bold focus:rounded-md focus:shadow-2xl focus:outline-none focus:ring-2 focus:ring-accent transition-all"
>
  Skip to main content
</a>
```

## 3. Global Focus-Visible Styling

All focusable elements (links, buttons, inputs, selects, textareas) use standardized `:focus-visible` styling declared in `app/globals.css`. Outline rings are never removed (`outline: none` without replacement is forbidden):

```css
/* Keyboard focus indicator — global a11y guarantee (dark & light sections) */
:focus-visible {
  outline: 2px solid var(--color-obsidian);
  outline-offset: 2px;
}

.on-dark :focus-visible,
section[class*="bg-[#0D0D0D]"] :focus-visible,
section[class*="bg-[#0A0A0A]"] :focus-visible,
section[class*="bg-obsidian"] :focus-visible {
  outline-color: #ffffff;
}
```

## 4. Form Control Standards & ARIA Architecture

Form implementations (`components/forms/RFQForm.tsx` and `components/forms/ContactForm.tsx`) follow strict WCAG-AA standards:

1. **Explicit Association:** Every `<input>`, `<select>`, and `<textarea>` must possess a unique `id` explicitly paired with `<label htmlFor="...">`. Floating labels or visual styling must maintain DOM accessibility.
2. **Required Fields:** Required fields carry both `required` and `aria-required="true"` (`name`, `email`, `businessType`, `budget`, `message`). Labels visibly indicate requirement (`*`) alongside screen-reader accessible clarification (`<span className="sr-only"> (required)</span>`).
3. **Invalid State & Error Messaging:**
   - Inputs carry `aria-invalid={Boolean(error)}` indicating form validation failure to assistive technologies.
   - RFQ Form: Error states are announced assertively using `<m.div id="rfq-form-error" role="alert" aria-live="assertive">`.
   - Contact Form: Form outcomes are announced via a polite live region `<div aria-live="polite" role="status">` with error alerts assigned `id="contact-form-error"` and `role="alert"`. Inputs wire `aria-describedby` dynamically to `contact-form-error` when an error is active.
4. **Field Descriptions & Hints:**
   - Supplementary hints use explicit `aria-describedby` references (e.g., `#rfq-email` referencing `<span id="rfq-email-hint">`).
5. **Honeypot Hidden Fields:** Bot-trapping honeypot inputs are removed from accessibility trees and tab sequences using `aria-hidden="true"`, `tabIndex={-1}`, and CSS hiding.

## 5. Keyboard-Only Traversal Walkthrough: /rfq

The Request for Quote (`/rfq`) form provides end-to-end keyboard operability without requiring mouse interaction:

1. **Entry & Skip Link:**
   - Press `Tab` upon page load -> Focus lands immediately on `Skip to main content`.
   - Press `Enter` -> Viewport jumps past Header navigation directly to `#main-content`.
2. **Company Details Section:**
   - Press `Tab` -> Focus moves to Full Name (`#rfq-name`). Active focus line transitions to brand emerald; label floats.
   - Enter text -> Press `Tab` -> Focus moves to Company Name (`#rfq-companyName`).
   - Press `Tab` -> Focus moves to Email (`#rfq-email`). Helper text is read programmatically.
3. **Project Goals Section:**
   - Press `Tab` -> Focus moves to Business Type dropdown (`#rfq-businessType`).
   - Press `Down Arrow` / `Up Arrow` -> Selects option (`Importer`, `Exporter`, `Trading Company`).
   - Press `Tab` -> Focus moves to Main Markets input (`#rfq-mainMarkets`).
   - Press `Tab` -> Focus moves to Project Vision textarea (`#rfq-message`). Multi-line input supported.
4. **Timeline & Budget Section:**
   - Press `Tab` -> Focus moves to Allocated Budget dropdown (`#rfq-budget`).
   - Press `Down Arrow` -> Selects budget tier (`$800–1.5k`, `$1.5–3k`, `$3k+`).
5. **Submission & Verification:**
   - Press `Tab` -> Focus lands on Submit button (`[ SUBMIT PROPOSAL REQUEST ]`) with distinct visible outline.
   - Press `Enter` or `Space` -> Form submits; loading state is announced; success/error response is surfaced to assistive technology via live regions.

### Acceptance Threshold
- **Zero Critical Violations**
- **Zero Serious Violations**
- Any newly introduced interactive element must maintain `focus-visible` styling and pass unit verification via `pnpm test`.

Before any pull request or card merge, verify:
1. `pnpm exec tsc --noEmit` exits 0 with zero type errors.
2. `pnpm test` passes all component and unit test suites.
3. `CARD_RISK=R1 bash scripts/agent/gate.sh` outputs `GATE OK`.
